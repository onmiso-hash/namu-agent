description: NAMU 세션 브리핑 — 최근 활동(시간순)·열린 task 전부(이 방 + 다른 방)·최근 교훈을 보여준다
---
NAMU "세션 브리핑"을 출력한다. 아래 순서대로 수행하고 마지막에 정해진 형식으로만 보여줘라. 파일을 수정·생성하지 말 것(읽기 전용).

1. 최근 활동 (시간순, task 무관, 이 방 한정):
   ```bash
   python scripts/namu_journal.py --limit 8
   ```
   여러 task의 `log.md`를 시간순으로 합쳐 출력한다. 각 줄: `<날짜시각> <machine> <task slug> [태그] <내용>`.

2. 열린 task 목록 — **이 방 + 다른 방 전체**(namu-63: 다른 폴더에서 세션을 열면
   그 방만 보여서 다른 프로젝트에 열려 있던 task를 통째로 놓치던 사고 방지):
   ```bash
   python scripts/namu_active_task.py --all --json
   ```
   JSON 배열이 나온다: `[{project, slug, title, last_ts, next}, ...]` (가장 최근 활동 순, 개인 풀 전체).
   `title`에는 task 이름(slug)이 들어 있지 않다(namu-64 — 만드는 쪽에서 걷어낸다). 그대로 `<slug> · <제목>`으로 이어 붙이면 된다.
   `project`가 현재 폴더명과 같으면 "이 방", 다르면 "다른 방"으로 나눠라(현재 폴더명은 `basename $(pwd)`로 구한다).
   `next`가 `null`이면 그 task는 "다음" 기록이 없는 것이다 — 조용히 빈칸으로 두지 말고 `(기록 없음)`이라고 명시하라.
   배열이 비어 있으면 "열린 task 없음"으로 간주한다.

3. `namu_recall`을 `limit=5`로 호출해 최근 교훈을 받는다.

4. 아래 형식으로만 출력(이 외 잡담 금지).

   **다른 방에 열린 task가 하나도 없으면** 기존 형식 그대로:

   🌳 NAMU 세션 브리핑

   🕘 최근 활동 (시간순, task 무관)
      <1단계 출력을 한 줄씩. 길면 줄여서>

   📂 열린 task <이 방 N>개

   #### ▸ <slug> · <제목>   최근 <MM-DD>
      다음: <next의 첫 문장>
      <next의 두 번째 문장>
      <next의 세 번째 문장…>

        <slug> · <제목>   최근 <MM-DD>   다음: <한 줄 요약 또는 (기록 없음)>

   **다른 방에 열린 task가 있으면** 이 방/다른 방을 나눠 보여준다:

   🌳 NAMU 세션 브리핑

   🕘 최근 활동 (시간순, task 무관, 이 방)
      <1단계 출력을 한 줄씩. 길면 줄여서>

   📂 열린 task — 이 방 <N>개 · 다른 방 <M>개

   이 방 (<현재 폴더명>)

   #### ▸ <slug> · <제목>   최근 <MM-DD>
      다음: <next의 첫 문장>
      <next의 두 번째 문장>
      <next의 세 번째 문장…>

        <slug> · <제목>   최근 <MM-DD>   다음: <한 줄 요약 또는 (기록 없음)>
   (이 방에 열린 task가 0개면 "이 방(<현재 폴더명>)에는 열린 작업이 없습니다 —
   이어가려면 그 폴더에서 세션을 여세요"라고 대신 알린다.)

   다른 방 <M>개
      <project>/<slug> · <제목>   최근 <MM-DD>
      ...
   (다른 방은 `다음:`을 붙이지 않는다 — 재진입은 그 폴더에서 세션을 열어야 의미가 있다.)

   두 형식 공통:

   열린 task는 **이 방 기준 5개까지, 다른 방은 3개까지** 보이고 나머지는 "… (N개 더)".

   ▸의 `다음:`은 **자르지 말고 전문으로** 싣는다 — 그 한 줄이 곧 재진입 지점이라
   잘리면 사용자가 이어가라고 해도 log.md를 다시 읽어야 착수할 수 있다. 단 원문이
   여러 문장이면 마침표·물음표·느낌표(+공백) 기준으로 문장 단위로 쪼개 한 줄에
   한 문장씩 하위 목록으로 보여준다(줄바꿈 없는 한 덩어리 문단은 읽기 불편하다는
   지적, namu-64) — 숫자 사이 마침표(`v0.1.39` 같은 버전 문자열)에서는 쪼개지
   않는다. ▸ 항목 자체는 제목 서식(굵게 강조)으로 표시해 나머지 목록과
   구분되게 한다. 나머지 task의 `다음:`은 여전히 한 줄 요약으로 줄여도 된다.

   💡 최근 교훈
      - <[outcome] task — reason>

   ▸가 가장 최근 활동한 task입니다(이 방에 열린 task가 있을 때만). "이어서 하자"고만
   하셔도 ▸의 `다음:`부터 갑니다 — 다른 걸 하시려면 이름을 대세요.
   상세가 필요하면 "recall로 상세 보여줘"라고 하세요.

**금지** — 열린 task가 여럿인데 하나만 "진행 중"으로 단정하지 말 것(목록은 전부 센다).
단 이 금지는 **"목록을 숨기지 마라"이지 "매번 되물어라"가 아니다** — 사용자가 대상을
지목하지 않고 "이어서 하자"고만 하면 되묻지 말고 ▸의 `다음:`부터 착수한다. 이어갈 지점은
이미 log의 마지막 `[다음]` 줄에 적혀 있으므로 다시 묻는 것은 사용자에게 답을 두 번
시키는 일이다(namu-57 사용자 지적). 다른 task를 원하면 사용자가 이름을 댄다.
"다음" 기록이 없는 task가 있으면 마지막에 한 줄로 알린다: 세션 끝에 `log.md`에 `[다음]` 태그 한 줄을 남기면 다음부터 표시된다고.
다른 방의 task를 "▸"로 추천하지 말 것(▸는 이 방에 열린 task 중에서만 고른다) — 다른 방으로 이어가려면 사용자가 먼저 그 폴더로 세션을 옮겨야 한다.
