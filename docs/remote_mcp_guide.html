직접 서버 운영하기

내 PC나 내 서버에서 나무를 실행해, 브라우저에서 쓰는 AI(claude.ai 등)에 기억을 붙입니다. 남의 서버에 기억을 맡기지 않는 대신, 서버를 직접 챙겨야 합니다.

여기가 맞는 길인지 먼저 확인하십시오

브라우저에서 쓰는 AI에 나무를 붙이는 방법은 두 가지입니다. 되는 일은 똑같고, 다른 것은 누가 서버를 챙기느냐뿐입니다.

나무 클라우드직접 서버 운영하기 (이 문서)
서버는 누가나무 쪽에서 대신 돌립니다여러분이 직접 돌립니다
기억 원본은 어디에여러분의 GitHub 비공개 저장소여러분의 PC 안 ~/.namu
준비물GitHub 계정PC 또는 상시 서버, 그리고 바깥에서 들어올 주소
드는 시간5분 안팎처음 붙일 때 30분 안팎
계속 챙길 것없음서버가 살아 있는지, 주소가 바뀌지 않았는지

그냥 쉽게 쓰고 싶으시다면 이 문서를 덮고 나무 클라우드로 가십시오. GitHub 계정만 있으면 설치도 카드 등록도 없이 5분이면 끝납니다. 기억을 남의 서버에 두기 싫으시거나, 이미 켜 둔 서버가 있으신 분만 이 문서를 따라오십시오.

터미널(검은 화면)에서 AI를 쓰신다면 이 문서가 아닙니다. 주소를 붙이는 것이 아니라 플러그인으로 설치하셔야 합니다. 주소로는 나무의 절반(기억)만 넘어가고, 대화 시작 브리핑·작업 절차·일꾼 AI는 따라오지 않습니다.

1. 웹으로 넘어가는 것과 안 넘어가는 것

나무는 두 부분입니다 — 기억과 작업 절차. 웹으로 연결하면 넘어가는 것은 기억뿐입니다.

✅ 웹에서 되는 것 (도구 열한 개)

  • 기억 꺼내기 · 찾기 · 남기기 (세 개 — 다섯 그릇 전부)
  • 작업일지 보기 · 쓰기 · 다른 방으로 옮기기 (옮기기가 한 개 — 보기·쓰기는 위의 세 개로 합니다)
  • 파일 올리기 · 목록 · 받기 · 지우기 (네 개)
  • 주고받는 일회용 링크 만들기 · 확인하기 (세 개)

❌ 웹에서 안 되는 것 (플러그인 전용 — 기능 셋과 도구 넷)

  • 대화를 열 때 지난 상황 자동 브리핑
  • /namu-task 작업 절차
  • 일꾼 AI(코더·검수) 부르기
  • 쪽지 떼기 · 책갈피 꽂기 · 빼기 (그 PC의 파일을 다루는 도구)
  • 여러 PC 동기화 켜기 (아래 참고)

브리핑이 없으니 첫 호출은 여러분이 시켜야 합니다. "나무 기억에서 recall 해봐"처럼 한마디 하시면 그다음부터는 AI가 알아서 씁니다.

작업일지를 쓸 때 한 가지 조건

작업일지를 남길 때는 어느 프로젝트인지 반드시 적어야 합니다. 터미널에서는 지금 열어 둔 폴더가 곧 프로젝트라 안 적어도 되지만, 웹에는 "지금 열어 둔 폴더"라는 것이 없기 때문입니다. 그냥 보기만 할 때는 안 적어도 전체를 합쳐서 보여줍니다.

파일 주고받기는 웹에서도 그대로 됩니다

브라우저 AI에서 만든 글이나 손에 든 파일을 그대로 올려 두고, 나중에 어느 AI에서든 다시 받을 수 있습니다. 파일은 여러분의 저장소로 가고, 나무는 "무슨 파일을 왜 올렸나"라는 이력만 갖습니다.

  • 이미 파일로 있는 것(그림·PDF·큰 파일)은 일회용 링크를 만들어 브라우저에서 바로 올립니다. 파일이 AI를 아예 안 거쳐서 크기와 상관없이 빠릅니다.
  • 대화에서 방금 쓴 글은 링크 없이 바로 올릴 수 있습니다.
  • 파일 몸통은 여러분의 각 PC로 안 내려옵니다. 목록에 뜨는 크기는 저장소가 아니라 첨부 기록에서 읽은 값입니다 — 저장소에 물으면 파일이 전부 내려와 이 격리가 무너지기 때문입니다.

동기화 켜기가 웹에서 막혀 있는 이유

동기화를 켜는 도구는 서버가 기억을 올려보낼 저장소 주소를 바꿉니다. 이것을 바깥에서 부를 수 있게 열어 두면, 남이 그 주소를 자기 것으로 바꿔 기억을 가로챌 수 있습니다. 그래서 웹에는 아예 내보내지 않고, 서버를 운영하는 사람이 서버 쪽에서 직접 설정합니다.

2. AI에게 맡기기

아래 절차는 네 단계 중 세 단계가 터미널 명령입니다. 그래서 Claude Code나 agy에게 통째로 맡길 수 있습니다. 이렇게 말씀하시면 됩니다.

나무 셀프호스팅을 붙이고 싶어.
docs/remote_mcp_guide.html 보고 서버 켜고 통로까지 열어줘.
단계누가 하나
① 서버 켜기AI가 대신 할 수 있습니다
② 바깥에서 들어올 통로 열기AI가 대신 할 수 있습니다
③ 연결이 진짜 되는지 확인AI가 대신 할 수 있습니다
④ 받은 주소를 AI 설정 화면에 붙이기사람이 해야 합니다 — 브라우저 화면에서 하는 일이라 터미널에서는 할 수 없습니다

맡기더라도 이것만은 직접 확인하십시오 — 서버를 인증 없이 띄운 채 바깥에 열면 여러분의 기억이 주소만 알면 누구나 볼 수 있는 상태가 됩니다. 아래 ①에서 열쇠를 반드시 넣고, "열쇠 없이 띄우기"는 내 PC 안에서 시험할 때만 쓰십시오.

3. 방법 ㉮ — 내 PC로 잠깐 써 보기

서버도 도메인도 없이 지금 쓰는 PC로 몇 분 만에 붙여 보는 방법입니다. 체험하기 좋습니다. 대신 PC를 계속 켜 두어야 하고, 통로 주소가 바뀔 때마다 AI 설정에 다시 등록해야 합니다.

  • 1

    서버를 켭니다

    이 단계에서 하는 일 — 내 PC 안에 나무 기억을 내주는 창구를 하나 엽니다. 아직 바깥에서는 닿을 수 없습니다.

    <아무도 못 맞힐 긴 문자열> 자리에는 비밀번호처럼 긴 문자열을 넣으십시오. 이 값이 곧 열쇠라, 이 값을 아는 사람만 들어올 수 있습니다.

    NAMU_HTTP_PATH_SECRET="<아무도 못 맞힐 긴 문자열>" \
  uv run --script namu-plugin/http_server.py

    이렇게 되면 성공 — 터미널이 멈춘 것처럼 보이며 서버가 계속 떠 있습니다. 이 창은 닫지 마십시오. 닫으면 서버도 함께 꺼집니다.

    플러그인으로 설치해 쓰고 계시다면 설치된 폴더에서 실행하십시오 (~/.claude/plugins/cache/namu-marketplace/namu/<버전>/).

  • 2

    바깥에서 들어올 통로를 엽니다

    이 단계에서 하는 일 — 내 PC의 창구에 인터넷에서도 닿을 수 있도록, 임시 주소를 하나 빌립니다. 이런 임시 통로를 터널이라고 부릅니다. 공유기 설정을 건드리지 않고도 바깥 주소를 받을 수 있습니다.

    ssh -p 443 -R0:localhost:8765 free.pinggy.io

    이렇게 되면 성공 — https://…로 시작하는 주소가 한두 개 찍힙니다. 이 주소를 적어 두십시오.

    무료 통로는 골라 써야 합니다. 직접 시험해 본 결과, 주소가 나온다고 해서 실제로 연결되는 것은 아니었습니다.

    • pinggy — 실제로 연결까지 됐습니다. 이 문서가 이것을 쓰는 이유입니다.
    • Cloudflare 임시 통로 — 주소는 나오는데 중간중간 실패했습니다.
    • localhost.run — 주소는 나오지만 요청이 내 PC까지 오지 않았습니다.

    무료 서비스는 상태가 계속 바뀌니, 어느 것을 쓰든 아래 3단계 확인을 꼭 거치십시오.

  • 3

    진짜 연결되는지 확인합니다

    이 단계에서 하는 일 — AI에 등록하기 전에, 그 주소로 실제 요청을 한 번 보내 봅니다. 여기서 거르지 않으면 "등록은 했는데 왜 안 되지?"로 한참 헤매게 됩니다.

    curl -sS -X POST "https://<받은 주소>/mcp/<아까 그 긴 문자열>" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"smoke","version":"0"}}}'

    이렇게 되면 성공 — "result"가 들어간 긴 응답이 돌아옵니다. 나무 서버가 자기소개를 하는 내용입니다.

    실패 신호 — 아무 응답 없이 한참 기다리거나, 연결이 거부되거나, 502 같은 숫자가 오면 통로가 안 뚫린 것입니다. 다른 통로로 바꾸십시오.

  • 4

    AI 설정에 주소를 붙입니다 사람이 하는 단계

    claude.ai 기준입니다 — 설정 → Connectors → Add custom connector.

    주소 칸에 이렇게 넣습니다. 맨 뒤 ?client=를 빠뜨리면 접속은 되는데 도구를 부를 때 거부당합니다.

    https://<받은 주소>/mcp/<그 긴 문자열>?client=claude

    client= 뒤에는 어떤 AI에서 쓰는지 알아볼 수 있는 이름을 아무거나 적으십시오. 나중에 기억을 볼 때 "이건 어디서 남긴 기억인지" 구분하는 데 쓰입니다.

    확인 — 대화창에서 "나무 기억에서 recall 해봐"라고 해 보십시오. 브리핑이 없으니 첫 호출은 이렇게 시켜야 합니다.

PC를 끄면 끊깁니다. 서버 창을 닫아도 마찬가지입니다. 계속 쓰시려면 아래 방법 ㉯로 가십시오.

4. 방법 ㉯ — 서버로 계속 쓰기

항상 켜져 있는 서버(집에 둔 작은 PC, 빌린 서버 등)와 바뀌지 않는 주소가 있을 때 씁니다. 주소가 고정이라 AI 설정에 딱 한 번만 등록하면 됩니다.

실제로 이 방식으로 배포해 본 적이 있습니다 — 웹에서 기억을 남기면 저장소로 올라가고, 그것을 다른 PC에서 그대로 꺼내 보는 것까지 확인했습니다.

준비물

  • 기억을 담을 비공개 저장소 — 터미널에서 쓰던 것을 그대로 써도 됩니다.
  • 그 저장소에 쓸 수 있는 열쇠 — GitHub에서 발급하는 개인 액세스 토큰입니다. 비밀번호 대신 쓰는 열쇠라고 보시면 됩니다. 남에게 보이거나 코드에 적어 넣으면 안 됩니다.
  • 바뀌지 않는 주소 — 도메인, 그리고 바깥 요청을 서버로 넘겨줄 중계 설정.

비밀 값을 어디에 두나

서버를 띄우려면 비밀 값 두 개가 필요합니다 — 기억을 올릴 저장소 주소와 들어올 때 쓸 열쇠입니다.

가장 권하는 방법은 서버에 .env 파일 하나를 두는 것입니다. 이유는 단순합니다 — 비밀 값이 그것을 쓰는 서버 한 곳에만 있으면, 새어 나갈 자리가 그만큼 적습니다. 중간에 거치는 곳이 많을수록 위험합니다.

비밀 값을 프로그램 안에 적어 넣지 마십시오. 한 번 적어 넣으면 그 사본을 가진 모든 곳에 열쇠가 같이 따라다닙니다. 항상 실행할 때 바깥에서 넣어 주십시오.

띄우기

나무는 서버용 실행 꾸러미를 함께 제공합니다 — deploy/ 폴더에 들어 있습니다. 서버에 파이썬을 깔고 설정을 맞추는 일을 매번 손으로 하지 않도록, 실행에 필요한 것을 통째로 묶어 둔 것이라고 보시면 됩니다.

  • 1

    꾸러미를 서버에서 한 번 만듭니다

    deploy/Dockerfile이 그 설계도입니다. 이 설계도로 실행 꾸러미를 만들어 두면, 그다음부터는 껐다 켜기만 하면 됩니다.

  • 2

    비밀 값을 담은 .env 파일을 같은 폴더에 둡니다

    앞에서 말한 두 값(저장소 주소, 들어올 때 쓸 열쇠)을 여기 적습니다. 이 파일은 절대 저장소에 올리지 마십시오.

  • 3

    띄웁니다

    docker-compose.yml이 "어떤 꾸러미를 어떤 설정으로 띄울지" 적어 둔 파일입니다. 이 파일이 있는 폴더에서 띄우면 서버가 살아납니다.

플랫폼에 맡기는 방식(Railway, Fly.io처럼 서버를 대신 운영해 주는 서비스)은 아직 확인해 본 적이 없습니다. 안 된다는 뜻이 아니라, 된다고 말할 근거가 아직 없다는 뜻입니다. 이 문서는 내 서버에 올리는 데까지만 다룹니다.

5. 안전하게 쓰기

  • 기록에 열쇠가 남습니다. 서버가 남기는 접속 기록에는 주소가 그대로 적히고, 그 주소에는 열쇠가 들어 있습니다. 이 기록을 남에게 보여주면 열쇠를 넘겨준 것과 같습니다. 새어 나간 것 같으면 바로 값을 바꾸고 서버를 다시 띄우십시오.
  • 통로를 닫을 때 열쇠도 바꾸십시오. 통로 주소는 만료돼도, 같은 열쇠를 다음에 또 쓰면 예전 기록에 남은 값이 여전히 유효합니다.
  • 암호화되지 않은 연결로 쓰지 마십시오. 나무 서버는 암호화를 직접 하지 않습니다 — 통로나 플랫폼이 대신합니다. 주소가 https로 시작하는지 확인하십시오.
  • "열쇠 없이 띄우기"는 내 PC 안에서만. 시험용으로 마련된 것이라, 바깥에 열면 주소를 아는 누구나 기억을 읽고 쓸 수 있습니다.

6. 막혔을 때 — 증상별

주소는 열렸는데 접속이 거부됩니다 (421이라는 숫자가 보입니다)

왜 그런가 — 나무 서버는 자기가 모르는 주소에서 들어오는 요청을 기본적으로 막습니다. 남이 여러분 PC 안쪽으로 요청을 밀어 넣는 공격을 막기 위한 장치인데, 통로를 거쳐 온 요청도 서버에는 모르는 주소로 보여 함께 막힙니다.

어떻게 푸나 — 서버를 켤 때 통로 주소를 허용 목록에 넣어 주십시오.

NAMU_HTTP_ALLOWED_HOSTS="내-통로-주소.example.com" \
  uv run --script namu-plugin/http_server.py

주소가 매번 바뀌어 미리 적을 수 없다면 *를 넣어 이 보호를 끌 수 있습니다. 다만 주소를 알 수 있는 상황이라면 *보다 실제 주소를 적는 편이 안전합니다.

접속은 되는데 도구를 부르면 거부당합니다

주소 맨 뒤의 ?client=가 빠졌을 가능성이 큽니다. 접속만 하는 단계는 이것 없이도 통과하지만, 실제로 기억을 꺼내거나 남길 때는 필요합니다.

통로 주소는 받았는데 확인 요청에 응답이 없습니다

주소가 나온 것과 실제로 연결이 이어지는 것은 별개입니다. 위 3장 3단계에서 직접 시험해 본 결과, 주소만 주고 연결은 안 되는 무료 통로가 있었습니다. 다른 통로로 바꾸십시오.

웹에서 남긴 기억이 다른 PC에서 안 보입니다

서버 쪽에서 저장소로 올려보내는 설정이 되어 있어야 합니다. 이 설정은 웹에서 켤 수 없고(1장 참고) 서버를 운영하는 분이 직접 넣어야 합니다.

작업일지를 남기려는데 거부당합니다

어느 프로젝트인지 적지 않으셨을 가능성이 큽니다. 웹에는 "지금 열어 둔 폴더"라는 개념이 없어서, 남길 때는 프로젝트 이름을 함께 적어야 합니다.

7. 설정값 목록

서버를 켤 때 명령 앞에 붙여 넣는 값들입니다. 필요한 것만 쓰시면 됩니다.

이름기본값무엇을 하나
NAMU_HTTP_PATH_SECRET없음주소에 넣는 열쇠. 넣으면 주소가 /mcp/<열쇠>로 바뀝니다. 가장 권하는 방식입니다
NAMU_HTTP_TOKEN없음주소 대신 요청 머리말에 실어 보내는 열쇠. AI 설정 화면에 머리말 입력칸이 있을 때 씁니다
NAMU_HTTP_ALLOWED_HOSTS내 PC만들어오는 요청을 허용할 주소 목록. 위 6장 첫 항목 참고. *는 이 보호를 끔
NAMU_HTTP_PORT8765서버가 쓸 문 번호
NAMU_HTTP_HOST127.0.0.1어느 주소로 요청을 받을지. 기본값은 내 PC 안에서만
NAMU_HTTP_PULL_INTERVAL60초다른 곳에서 바뀐 기억을 얼마나 자주 받아올지. 0이면 요청마다
NAMU_HTTP_ALLOW_NOAUTH꺼짐열쇠 없이 띄우기. 내 PC 안 시험용입니다 — 바깥에 열지 마십시오
NAMU_MACHINE컴퓨터 이름여기서 남긴 기억에 찍히는 출처 이름
NAMU_SYNC_REMOTE없음서버용. 기억을 담아 둘 저장소 주소(열쇠 포함)
