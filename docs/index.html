1. 나무가 뭔가요

AI에게 붙이는 기억 장치입니다. 지금 쓰는 AI는 대화를 닫는 순간 전부 잊습니다. 어제 무엇을 정했는지, 왜 그렇게 정했는지, 지난주에 어디서 막혔는지 — 다음 대화에서 처음부터 다시 설명해야 합니다.

나무는 그것을 파일로 남깁니다. 그리고 다음 대화가 시작될 때 알아서 다시 꺼내 놓습니다.

다른 기억 기능과 무엇이 다른가 — 나무는 결과만이 아니라 왜 그렇게 했는지(이유)를 함께 남깁니다. 이유가 없으면 다음에 같은 논의를 처음부터 되풀이하게 되기 때문입니다. 그래서 나무의 기억은 한 건마다 무엇을 · 왜 · 그때 무슨 일이 세 층으로 남습니다.

또 하나 — 기억은 여러분의 파일로 남습니다. 특정 회사의 서버 안에 갇히지 않습니다. AI를 바꿔도 기억은 그대로 따라옵니다.

2. 무엇을 기억하나요

성격이 다른 기억을 한 통에 담으면 나중에 아무것도 찾을 수 없습니다. 그래서 나무는 네 개의 그릇에 나눠 담습니다.

📚 교훈

다시 쓸 배움. "이 방식은 이래서 실패했다", "이 설계를 고른 이유는 이것이다" 같은 것.

👤 개인 사실

여러분에 대한 사실. 쓰는 기기, 일하는 방식, AI에게 바라는 것.

📋 작업일지

진행 기록. 무슨 작업이 열려 있고 어디까지 했는지.

🗒️ 쪽지

쓰고 버리는 메모. 네 그릇 중 유일하게 뗄 수 있습니다.

AI는 이 그릇들을 다루는 도구 일곱 개를 갖습니다 — 기억을 꺼내기·찾기·남기기, 쪽지 떼기, 책갈피 꽂기·빼기, 그리고 다른 PC와 맞추기입니다. 여러분이 도구 이름을 외울 필요는 없습니다. "지난번에 정한 거 뭐였지?"라고 물으면 AI가 알아서 꺼냅니다.

기억이 어디에 어떻게 쌓이는지 자세히 보려면 → 기억 설계도

3. 쓰는 방법은 네 갈래입니다

나무를 어디에 붙이느냐에 따라 설치 방법도, 할 수 있는 일도 달라집니다. 먼저 전체를 한눈에 보십시오.

왜 웹에서는 절반만 되나요? 나무는 두 부분으로 되어 있습니다 — 기억과 일하는 절차입니다. 웹으로 연결하면 넘어가는 것은 기억뿐입니다. 대화를 시작할 때 지난 상황을 알아서 보여주는 브리핑, 여러 단계 작업을 순서대로 돌리는 절차, 일꾼 AI를 불러 코드를 맡기는 기능 — 이것들은 터미널 쪽에만 들어 있습니다.

5. 웹으로 쓸 때 — 두 갈래의 차이

웹에서 쓰는 방법이 둘인데, 되는 일은 똑같습니다. 다른 것은 누가 서버를 돌리느냐와 기억의 원본이 어디에 남느냐입니다.

③ 나무 클라우드④ 직접 서버 돌리기
서버는 누가 돌리나나무 쪽에서 대신 돌립니다여러분이 직접 돌립니다
기억의 원본은 어디에여러분의 GitHub 비공개 저장소
서버가 갖는 것은 사본뿐		여러분의 PC 안 ~/.namu 폴더

나무 클라우드

서버를 직접 돌리지 않고 웹 AI에 기억을 붙이는 가장 쉬운 길입니다. GitHub 계정만 있으면 되고, 카드 등록은 없습니다. 로그인하면 여러분 계정에 비공개 저장소 하나를 마련하고, 나만의 접속 주소를 하나 받습니다. 그 주소를 쓰는 AI에 붙이면 끝입니다.

기억의 원본은 여러분 저장소에 남습니다. 그만두고 싶으면 주소를 폐기하고 저장소를 가져가면 됩니다.

가입 절차·안전·자주 묻는 것은 모두 그 사이트에서 안내합니다.

직접 서버 돌리기

기억을 남의 서버에 두고 싶지 않거나, 이미 상시 켜둔 서버가 있다면 이쪽입니다. 서버를 켜고 → 밖에서 접속할 통로를 열고 → 그 주소를 AI에 붙이는 순서입니다.

이 과정은 AI에게 맡길 수 있습니다. 자세한 것은 웹에서 직접 서버 돌리기를 보십시오.
