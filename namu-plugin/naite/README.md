# 나이테 — 세션 기록을 읽어 어긋난 자리를 찾는다

이 폴더는 2026-09-09까지 별도 저장소(`onmiso-hash/naite`)였다. 자체 개선 고리를
나무가 맡는 이상 그것을 재는 도구도 나무와 함께 퍼져야 하므로 플러그인 안으로
들여왔고, 옛 저장소는 지웠다. 앞으로 나이테는 여기서만 고친다.

나무가 **기억을 남기는** 도구라면, 나이테는 **이미 남은 것을 되돌아보는** 도구다.

## 무엇을 읽나

`~/.claude/projects/<폴더키>/<세션id>.jsonl`

줄마다 JSON 하나가 들어 있다. `type` 값으로 갈린다.

| type | 무엇 |
|---|---|
| `user` | 사람 발화와 도구 결과가 **섞여 있다** — 갈라내야 한다 |
| `assistant` | AI 응답과 도구 호출 |
| `cost-state` | 세션 결산 — 총 시간·비용·모델별 토큰 (세션당 한 줄) |
| `attachment` · `system` · `file-history-snapshot` | 부속 기록 |

되돌림 표지는 줄의 최상위 칸에도 따로 남는다.

| 칸 | 무엇 |
|---|---|
| `interruptedMessageId` | 사용자가 요청을 중간에 끊었다 |
| `toolDenialKind` | 사용자가 도구 호출을 거절했다 |
| `userFeedback` | 사용자가 되물었다 |

## 쓰는 법

```
python3 naite.py 되돌림                  최근 7일 — 요약만
python3 naite.py 되돌림 --자세히         낱낱을 표로 늘어놓는다
python3 naite.py 되돌림 --최근 30        최근 30일
python3 naite.py 되돌림 --전부           전체 기간
python3 naite.py 되돌림 --날 2026-09-04  그날 하루
python3 naite.py 되돌림 --방 naite       그 폴더에서 연 세션만
python3 naite.py 되돌림 --원문           발화를 자르지 않는다(--자세히를 겸한다)
python3 naite.py 되돌림 --넓게           약한 신호까지 (오탐이 크게 는다)

python3 check_incidents.py               사고를 실제로 짚는지 확인
```

**기본은 요약이다.** 30일치 낱낱은 190줄이 넘어 화면에 담기지 않는다. 그래서
먼저 갈래·날짜·방·세션으로 어디에 몰렸는지만 보여주고, 낱낱은 `--자세히`로 뺐다.

요약에 나오는 날짜와 방은 그대로 파고드는 열쇠다. 표에 뜬 날짜를 `--날`에,
방 이름을 `--방`에 넣으면 그 범위만 다시 요약해 준다. 범위를 충분히 좁힌 뒤에
`--자세히`를 붙이는 것이 이 도구를 쓰는 정상 경로다.

### 요약이 보여주는 것

| 칸 | 무엇 | 무엇에 쓰나 |
|---|---|---|
| 갈래 | 요청 중단 · 도구 거절 · 말로 반박의 건수 | 구조 표지와 판정한 것의 비중을 가른다 |
| 많이 나온 날 | 상위 5일과 막대 | 답답했던 날을 짚어 `--날`로 판다 |
| 많이 나온 방 | 폴더별 건수 | 어느 프로젝트에서 많이 어긋났나 |
| 몰린 세션 | 상위 5개 세션 | 한 세션에서 되풀이된 자리를 찾는다 |
| 자주 걸린 신호 | 어느 낱말 규칙에 걸렸나 | 규칙이 한쪽으로 쏠렸는지 본다 |

이미 `--날`이나 `--방`으로 좁힌 경우, 그 칸은 한 줄뿐이라 자동으로 감춘다.

`check_incidents.py`는 나무에 교훈으로 남은 사고 네 건을 걸어 두고, 그 사고를
촉발한 발화가 실제로 잡히는지 본다. **판정 규칙을 고쳤으면 반드시 이것부터 돌린다** —
오탐을 줄이려다 사고를 놓치게 되는 것이 이 도구의 가장 위험한 실패다.

## 지금까지 잰 정확도 (2026-09-09, 기록 45개 전체)

말로 반박 판정을 손으로 전수 검사하고 규칙을 고친 결과다. 세션 기록은 약 28일치만
남으므로 2026-09-05에 잰 값(94건 중 오탐 22건)과는 표본 자체가 다르다.

| | 규칙을 고치기 전 | 고친 뒤 |
|---|---|---|
| 말로 반박 (판정한 것) | 70 | 64 |
| 그중 진짜 되돌림 | 51 | 52 |
| 그중 잘못 잡은 것 | 19 (27%) | 12 (19%) |

구조 표지(요청 중단 31건·도구 거절 48건)는 기록에 그대로 남은 것이라 틀리지 않는다.

**무엇을 고쳐서 줄였나.** 오탐 19건을 유형별로 세어 보니 "설치된 거 맞아?" 같은
단순 확인 질문이 일곱 건으로 가장 컸다. 그래서 `맞아?·맞지?`를 잡던 '확인 추궁'을
강한 신호에서 약한 신호로 내렸다. 그것만 하면 사용자가 앞뒤 모순을 짚은 진짜
되돌림 세 건까지 함께 놓치므로, 그 세 건이 공통으로 쓰던 말투를 '모순 지적'과
'사실 정정' 두 신호로 새로 세워 강한 신호에 더했다. 그 결과 진짜 되돌림은 한 건도
잃지 않고 오탐만 일곱 건이 빠졌으며, 사고를 촉발한 발화("안온게 아니라 내가
지운거야") 한 건이 새로 잡혔다.

**남은 오탐 12건의 유형은 둘이다.** ①"~있잖아"로 되짚으며 새 요청을 꺼내는 말
②상황 설명·자기 정정·화해. 둘 다 '되짚음' 신호에 걸리는데, 이 신호는 단독으로
진짜 되돌림 열세 건을 잡고 있어 내리면 손해가 훨씬 크다.

**놓친 것의 비율은 아직 모른다.** 세션 첫 발화를 뺀 사람 발화 586건 전부를 손으로
판정해야 알 수 있고, 지금은 사고 네 건이 모두 잡히는 것으로 대신했다. 이 한계를
숨기지 말 것.

## 지킬 것

**세는 것과 판단하는 것을 섞지 않는다.** 되돌림을 찾는 일은 기록에 있는 표지를 세는 것이고, 그것이 무슨 사고였는지 해석하는 일은 별개다. 앞의 것이 틀리면 뒤의 것은 전부 헛것이 된다.

**잘못 잡은 것을 숨기지 않는다.** 되돌림 판정은 표현이 다양해서 반드시 놓치거나 잘못 잡는다. 정확도를 세어 함께 보고하지 않으면, 이 도구는 그럴듯한 표를 보여 주면서 사실은 아무것도 못 짚는 물건이 된다.

**기록을 고치지 않는다.** 세션 기록은 읽기만 한다.

## 기록

나이테를 고친 일은 `namu-agent` 방에 적는다. 나이테가 나무 본체의 일부가 되었기 때문이다.
